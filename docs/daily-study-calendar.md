# 毎日の記録

歯車の「効果音」の下からカレンダーを開く。Google/Apple等の登録アカウントが実在する問題を1問回答すると、日本時間の日付で1日1個記録する。正誤は問わない。ユーザー行ロック・日付の一意制約で重複を防ぎ、図鑑への所有登録も同じトランザクションで行う。

通常と当季節の、画像の存在するスタンプを同じ抽選プールにする。既に所有しているものも抽選対象。図鑑の所有は重複させず、カレンダーには毎日の結果を残す。期間終了後も獲得済みスタンプは閲覧可能。既存の回答数節目の報酬は独立したカウンターで継続する。

春3〜5月、夏6〜8月、秋9〜11月、冬12〜2月。個別イベント分類はハロウィン10月、クリスマス12月、お正月1月。現時点の画像は通常59個と夏50個。追加イベントは画像とStampレコードを対応するseasonで登録してから抽選される。

## 公開手順

1. CIのDaily calendar checkが成功していることを確認する。
2. mainへの取り込み後、Renderのリリース時に `bundle exec rails db:migrate` を実行してから新しいアプリプロセスを起動する。自動デプロイ設定とマイグレーション実行箇所はRender側で確認する。
3. 2本のマイグレーションで記録テーブル・報酬カウンター・既存画像のカタログが登録される。既存の獲得履歴は維持する。
4. 登録アカウントで1問回答し、結果画面・カレンダー・図鑑を確認する。同日に再回答しても日付のスタンプは増えない。

CapacitorはRenderのURLを表示する構成なので、このRails側の変更にネイティブビルドは不要。Macのローカルソースは別途git pullで同期する。本PRは公開操作を含まない。

小さい画面・拡大文字設定では操作を切り落とさずスクロールを許容し、通常のスマホサイズで結果画面が収まるよう円・余白・画像を縮小している。
